## Context

Every day/night slot of the calendar gets an employee. We must store which employee works which slot, whether it was set by hand or generated, and the data the rules need (vacations, first/last day of work). Time of day does not matter, only whether a shift is the day shift, the night shift, or (for rules) both.

## Decision (proposal)

- A **slot** is `{ date: 'YYYY-MM-DD', part: 'day' | 'night' }`. Dates are plain ISO strings with no time zone and no clock time. Rules that talk about a whole day use `part: 'both'`, which expands to the day and night slots.
- **Assignments** are stored per slot: `{ employeeId, source: 'manual' | 'auto' }`. One employee per slot.
- **Manual assignments are locked**: the generator never changes or removes them. They can be set on any date, including the past. Clicking a manual tile lets the user clear it.
- Data lives in the same data file as employees (`data/local.json` for the MVP, ADR-514da88), validated with zod. Hosted storage stays deferred (ADR-112163d).
- Employee records gain optional fields: first working slot, last working slot, vacations (`from` slot to `to` slot).

## Open questions

- Do manual assignments that break a rule get a warning marker (recommended) or are they blocked?
- Do manual assignments count toward fairness and shift-sequence limits (recommended: yes)?
