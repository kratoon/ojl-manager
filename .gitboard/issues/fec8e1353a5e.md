## Definition: shift and slot

A **shift** (slot) is one specific **date** plus either **day** or **night**: `{ date: 'YYYY-MM-DD', part: 'day' | 'night' }`. Every date has exactly two shifts. Clock times are never stored or needed. Rules that span a whole date use `part: 'both'` as shorthand for "the day shift and the night shift of that date". There is no other kind of shift.

## Context

Every shift gets one employee. We must store who works which shift, whether it was set by hand or generated, and the data the rules need (vacations, first/last shift).

## Decision

- Dates are plain ISO strings (no time zone, no clock time).
- **Assignments** are stored per shift: `{ employeeId, source: 'manual' | 'auto' }`. One employee per shift.
- **Manual assignments are locked**: the generator never changes or removes them. They can be set on any date, including the past. Clicking a manual tile lets the user clear it. Tiles show a lock icon in the corner.
- A manual assignment that breaks a rule is **allowed but shows a warning**. Manual assignments count toward fairness and sequence limits.
- Data lives in the same data file as employees (`data/local.json` for the MVP, ADR-514da88), validated with zod. Hosted storage stays deferred (ADR-112163d).
- Employee records gain optional fields: first shift, last shift, vacations (each: `from` shift to `to` shift, plus a `compensate` flag, see ADR-4a9d8da), per-employee overrides (max shifts in a row, allow one day+night pair, see ADR-86a9b67).
