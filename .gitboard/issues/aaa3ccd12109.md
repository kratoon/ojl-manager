## Context

Rules currently answer yes/no: may this employee work this shift. We want the engine ready for preferences, so an assignment gets a **preference score** instead of a boolean. This amends the "all rules are hard constraints" wording of ADR-86a9b67 and the selection step of ADR-4a9d8da.

## Proposal

### Scale
- A verdict is an integer **0 to 5**. **0 = cannot be assigned** (today's "no", always a hard block). 1 to 5 = allowed, higher is more preferred. 3 is neutral.

### Rules return a verdict or no opinion
- Each rule returns `{ score: 0..5, reason }` or **`null` (no opinion)**.
- Every existing rule maps to **0 when violated and `null` when satisfied**. A satisfied hard rule must not return 5, otherwise hard rules would inflate the score.
- Preference rules (future) return 1 to 5 for the shifts they care about and `null` elsewhere.

### Combining verdicts for one employee and shift
- Any rule returning 0 makes the final score **0** (forbidden), whatever the others say.
- Otherwise the final score is the **weighted average** of the non-null scores (weight defaults to 1 per rule, configurable per rule type later). No opinions at all gives the neutral score 3.
- Average instead of minimum, so one mild "2" does not outweigh several "5"s. Minimum would make the weakest rule always win.

### Choosing an employee for a shift
Candidates with final score above 0 are ordered by:
1. highest final score (a 5 beats a 2),
2. then fairness: largest gap between target and shifts worked (ADR-4a9d8da),
3. then the fixed tie-break (last name, first name, id).

With no preference rules every candidate scores the same, so behaviour equals today's fairness-only choice.

### Trade-off to be aware of
Score first means preferences can pull the shift counts apart (an employee everyone scores 5 for takes the shifts). A later option is a fairness tolerance (only candidates within N shifts of their target compete on score). The comparator is a single replaceable function, so this can change without touching rules.

### Other points
- The score and its reasons are returned with each assignment, so the preview and tile warnings can say why.
- Manual assignments ignore scores (they are locked); a score of 0 for a manual assignment shows the warning from ADR-fec8e13.
- Determinism (ADR-4a9d8da) still holds: scores are pure functions of the inputs.

## Open questions

- Is 0 to 5 enough resolution, or should the scale be wider (e.g. 0 to 10) for room?
- Score first then fairness (proposed), or fairness first then score, or a tolerance?

## Acceptance Criteria

- [ ] Scale and meaning of 0 agreed
- [ ] Rules return a verdict or no opinion (satisfied hard rule = no opinion)
- [ ] Combination rule agreed (zero wins, otherwise weighted average)
- [ ] Ordering of score vs fairness agreed
- [ ] Decision accepted
