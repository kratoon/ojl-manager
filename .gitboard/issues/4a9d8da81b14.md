## Context

A "regenerate" action fills shifts while following all rules, leaving manual (locked) assignments untouched. Rules change over time, so the calculation must be driven by the configured rules, not hardcoded.

## Decision

- The scheduler is a **pure, deterministic function** `generate({ employees, rules, assignments, from, to })` returning the proposed assignments plus the shifts it could not fill and why. No UI or storage inside it, so it is unit-testable.
- **Preview is mandatory.** Regenerate never writes directly: it shows a preview (changed shifts highlighted, unfilled shifts with reasons, warnings) and the user confirms or cancels.
- **Start shift is selectable**: the user can regenerate from a specific shift (date + day/night). The range ends at the last calendar month. Auto assignments in the range are recomputed; manual assignments are kept.
- Strategy: walk shifts chronologically; for each empty shift take the eligible employees (all constraints pass) and choose by **fairness** (below), with a stable tie-break so results are reproducible. A shift with nobody eligible stays **empty** and is highlighted with the reason.
- Greedy can dead-end on tight rules. Accepted for the MVP; a backtracking or constraint-solver step can replace the strategy later without changing the interface.
- Empty (unset) shifts are highlighted. Shifts closed by company rules are shown as closed, not as unset.

### Fairness

Goal: the total number of shifts per employee is similar for everyone over the calendar range. Each employee has a **target** share. Vacation changes the target per vacation, via a checkbox **`compensate`** on each vacation:
- `compensate` off ("okay to have fewer shifts"): the vacation shifts are not counted, so the employee's target shrinks accordingly.
- `compensate` on ("PTO taken into account"): the missed shifts are made up, so the target stays unchanged and the employee gets more shifts around the PTO.

The generator prefers the employee with the largest gap between target and shifts already worked (manual assignments included).

## Open questions

- Regenerate range: the first request said "from today, today not modified". The latest says the start can be chosen, defaulting to **today's day shift**. Is today's day shift included (modified) by default, or does the default start after today?
- Default value of the `compensate` checkbox for a new vacation (assumed off).
