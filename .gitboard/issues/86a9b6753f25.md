## Context

Rules will keep being added and can live in different places: company-wide, per employee, or per date/slot. Examples: last/first shift of an employee, vacation from slot to slot, a slot fixed to an employee, a slot an employee cannot work, company working days, company closed from slot to slot, max N shifts in sequence, no day+night together.

## Decision (proposal)

- Rules are **stored where they belong** (company config, employee record, date rules) so each can be edited in the right screen.
- At calculation time all sources are **normalised into one list of constraints**, so the engine does not care where a rule came from.
- Each rule type is a small registered unit: a zod schema plus a function that says whether an employee may work a given slot given the current schedule. Adding a rule type means adding one unit and its tests, not changing the engine.
- Initial rule types:
  - company: working weekdays (e.g. MON-SUN), closed period (slot to slot), max shifts in sequence of the same kind, no day+night on the same date
  - employee: first shift, last shift, vacation (slot to slot), optional override of the company sequence limit
  - date: slot fixed to an employee, slot forbidden for an employee
- All rules are **hard constraints**. There are no soft or weighted rules for now.

## Open questions

- Is the max-in-sequence limit company-wide with per-employee override, or only per employee?
- Does a night shift between two day shifts break a day-shift sequence?
- Any rest rule between a night shift and the next day shift? (None assumed.)
